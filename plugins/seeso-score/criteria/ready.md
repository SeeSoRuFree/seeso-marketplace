# Ready 판단 기준서

> 이 문서는 에이전트가 읽고 코드베이스를 판단하는 기준입니다.
> 항목당 0-2점 (0=미흡, 1=부분적, 2=충분), 총 10항목, 만점 20점.

---

## A. 구조 (Structure)

### A1. 프로젝트 구조 명확성
- **탐색**: 프로젝트 루트 ls, src/ 또는 app/ 구조
- **0점**: 파일이 뒤죽박죽, 관심사 분리 없음
- **1점**: 대략적 분리는 되어있으나 일관성 부족
- **2점**: 명확한 레이어 분리 (routes/models/services 등), 일관된 네이밍

### A2. 환경 분리
- **탐색**: .env, .env.example, docker-compose, terraform/, config 파일들
- **0점**: 환경 구분 없음, 설정값 하드코딩
- **1점**: .env 있으나 환경별 분리 불완전 (예: API URL 하드코딩)
- **2점**: dev/staging/prod 분리, 환경별 설정 관리, .env.example 완비

---

## B. 배포 가능성 (Deployability)

### B1. 배포 파이프라인
- **탐색**: Dockerfile, docker-compose.yml, vercel.json, .github/workflows/, terraform/
- **0점**: 배포 설정 전무, "어떻게 배포하는지" 불명
- **1점**: Dockerfile 있으나 CI/CD 없음, 또는 일부만 존재
- **2점**: CI/CD + 컨테이너/IaC 구성 완료, push→배포 경로 명확

### B2. 시크릿 관리
- **탐색**: git history에서 .env 여부, 코드 내 하드코딩 시크릿, .gitignore
- **검색 패턴**: `SECRET`, `PASSWORD`, `API_KEY`, `TOKEN` 등이 코드에 값과 함께 있는지
- **0점**: 하드코딩된 시크릿 또는 .env가 git에 포함
- **1점**: .env.example 있으나 코드에 디폴트 시크릿 존재 (예: "dev-secret-key")
- **2점**: 시크릿 외부 관리 (SSM, Vault 등), 코드에 민감정보 없음

### B3. 시드 데이터
- **탐색**: seed 스크립트, fixtures/, migrations/에 데이터 포함 여부, README의 초기 설정
- **0점**: 시드 없음, 빈 DB로 시작하면 서비스 불가
- **1점**: 시드 스크립트 있으나 불완전 (일부 마스터 데이터 누락)
- **2점**: 마스터 데이터 + 테스트 데이터 시드 완비, 실행 방법 문서화

---

## C. 완성도 (Completeness)

### C1. 데이터 모델 완성도
- **탐색**: models/ 디렉토리, 마이그레이션 파일, 관계 정의, 인덱스/제약조건
- **0점**: 핵심 엔티티 누락 또는 관계 없음
- **1점**: 엔티티 있으나 관계/제약조건 불완전
- **2점**: 기획 대비 데이터 모델 완전, 마이그레이션 전략(Alembic/Prisma 등) 있음

### C2. 인증/인가 경계
- **탐색**: auth 관련 파일, 미들웨어, JWT/세션 설정, 역할별 접근 제어
- **0점**: 인증 없음
- **1점**: 인증 있으나 역할별 접근 제어 미흡 (예: seeker가 employer API 호출 가능)
- **2점**: 인증 + 역할 기반 접근 제어 동작, 우회 불가

---

## D. 운영 준비 (Operational)

### D1. 비용 구조
- **탐색**: 외부 API 호출 (OpenAI, AWS 등), rate limit 코드, 캐싱 전략
- **0점**: 외부 API 무제한 호출, 비용 폭증 가능
- **1점**: 일부 제한 있으나 완전하지 않음
- **2점**: rate limit + budget cap 설정, 비용 예측 가능

### D2. 에러 복구
- **탐색**: 헬스체크, try-catch 전략, fallback 패턴, SPOF 존재 여부
- **0점**: 단일 장애점이 전체 서비스를 죽임
- **1점**: 헬스체크 있으나 graceful degradation 없음
- **2점**: graceful degradation, 장애 격리, 헬스체크 완비

### D3. 데이터 안전성
- **탐색**: 백업 설정, 마이그레이션 도구, 개인정보 처리 (민감 데이터 다루는 경우)
- **0점**: 백업/복구 전략 없음
- **1점**: 마이그레이션 있으나 백업 없음
- **2점**: 마이그레이션 + 백업 전략 + 민감 데이터 보호

---

## 출력 규칙

1. 항목별로 **점수 + 근거 한 줄** 필수
2. **0점 항목은 Critical Blockers**로 별도 강조
3. **Top 3 개선 권장** 제시 (점수 상승폭 큰 순)
4. 전체 점수는 `Ready: X/20 (Y%)` 형태

## 커스터마이징

프로젝트별로 이 기준서를 복사해서 수정 가능:
- 항목 추가/제거 (예: 모바일이면 "앱 빌드 설정" 추가)
- 가중치 변경 (예: MVP면 B3 시드를 3점으로)
- 프로젝트 컨텍스트 추가 (예: "Vercel 배포 기준으로 판단")
