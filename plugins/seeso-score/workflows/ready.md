# Ready 워크플로우

## 목적
"이 프로젝트를 실제로 프로덕션에 올려서 쓸 수 있는가?" AI 판단

## 핵심 원칙
- **읽기 전용** — 빌드/테스트 실행하지 않음 (그건 Code 종목)
- **판단만** — 파일을 읽고 구조를 분석하고 점수를 매김
- **2분 이내** — 빠르게 완료

## 실행 순서

### Step 1: 판단 기준서 로드
`criteria/ready.md` 를 읽어서 10개 항목과 채점 기준을 인지한다.

### Step 2: 프로젝트 스캔
전체 구조를 파악한다:
```
- Glob으로 파일 트리 파악 (프로젝트 루트 전체)
- CLAUDE.md, README.md 읽기 (프로젝트 컨텍스트)
- package.json, pyproject.toml 읽기 (의존성, 스크립트)
- Dockerfile, docker-compose.yml 읽기 (배포 설정)
- .env.example 읽기 (환경 변수)
- .gitignore 읽기 (시크릿 보호)
- terraform/, .github/workflows/ 존재 확인
```

### Step 3: 항목별 판단 (순차)
criteria/ready.md의 각 항목(A1~D3)에 대해:
1. 해당 항목의 **탐색** 지시에 따라 관련 파일 탐색
2. 필요시 Grep으로 패턴 검색 (예: 하드코딩 시크릿)
3. 0/1/2점 채점
4. 근거 한 줄 기록

### Step 4: 결과 출력
```markdown
Ready: [점수]/20 ([%])

| 항목 | 점수 | 근거 |
|------|------|------|
| A1 프로젝트 구조 | ?/2 | ... |
| A2 환경 분리 | ?/2 | ... |
| B1 배포 파이프라인 | ?/2 | ... |
| B2 시크릿 관리 | ?/2 | ... |
| B3 시드 데이터 | ?/2 | ... |
| C1 데이터 모델 | ?/2 | ... |
| C2 인증/인가 | ?/2 | ... |
| D1 비용 구조 | ?/2 | ... |
| D2 에러 복구 | ?/2 | ... |
| D3 데이터 안전성 | ?/2 | ... |

Critical Blockers: (0점 항목)
- ...

Top 3 개선 권장: (점수 상승폭 큰 순)
1. ...
2. ...
3. ...
```
